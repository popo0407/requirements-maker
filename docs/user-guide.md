# ユーザーガイド

## はじめに

Requirements Makerは、ソフトウェア開発の上流工程を効率化するAI支援型共同編集システムです。

## アカウント作成とログイン

1. トップページにアクセス
2. 「新規登録」をクリック
3. メールアドレスとパスワードを入力
4. 確認メールのリンクをクリックして認証完了

## プロジェクトの作成

1. ダッシュボードで「新しいプロジェクト」をクリック
2. プロジェクト名と説明を入力
3. 「作成」ボタンをクリック

## メンバー管理

### メンバーの招待

1. プロジェクトページで「メンバー」タブを開く
2. 「メンバーを追加」をクリック
3. メールアドレスを入力
4. ロールを選択（オーナー/編集者/閲覧者）
5. 「招待」をクリック

### ロール権限

- **オーナー**: 全ての操作が可能（フェーズ完了、メンバー管理、プロジェクト削除）
- **編集者**: 編集が可能（フェーズデータの編集、コメント追加）
- **閲覧者**: 閲覧のみ可能

## フェーズの進め方

### 1. アイデアフェーズ

**目的**: プロジェクトのアイデアを自由に書き出し、整理する

**使い方**:
1. 「アイデア追加」ボタンでアイデアを入力
2. 複数人で同時に編集可能
3. タグを付けて分類
4. AI支援機能:
   - 「要約」: アイデアを要約・分類
   - 「カテゴリ分け」: 自動的にカテゴリ化

**完了条件**:
- AI要約が生成されている

**AI支援の使い方**:
```
1. 「AI支援」ボタンをクリック
2. 「要約」を選択
3. AIの提案を確認
4. 採用または破棄を選択
```

### 2. 要件定義フェーズ

**目的**: アイデアを構造化された要件に変換する

**使い方**:
1. 「機能要件」「非機能要件」「制約条件」を入力
2. 各要件に優先度を設定
3. 不明確な点は「未確定事項」に記録
4. AI支援機能:
   - 「アイデアから変換」: アイデアを要件に変換
   - 「曖昧さチェック」: 曖昧な表現を指摘
   - 「抜け漏れチェック」: 不足している要件を提案

**完了条件**:
- 未確定事項が0件
- 最低1つの機能要件が存在

**要件の書き方**:
```
良い例:
"ユーザーはログイン後、1秒以内にダッシュボードを表示できる"

悪い例:
"素早くダッシュボードを表示する"
```

### 3. 設計計画フェーズ

**目的**: 技術方針とアーキテクチャを決定する

**使い方**:
1. 技術スタックを選択（フロントエンド、バックエンド、データベース等）
2. アーキテクチャ概要を記述
3. コンポーネント構成を定義
4. AI支援機能:
   - 「整合性チェック」: 要件とアーキテクチャの整合性を確認

**完了条件**:
- 技術スタックが定義されている
- アーキテクチャ概要が記述されている

**アーキテクチャの記述例**:
```
システム概要:
3層アーキテクチャ（プレゼンテーション層、ビジネスロジック層、データ層）

主要コンポーネント:
- フロントエンド: React SPA
- API層: REST API (Node.js)
- データベース: PostgreSQL
```

### 4. 設計書作成フェーズ

**目的**: 最終的な設計書を生成・編集する

**使い方**:
1. 「設計書生成」ボタンでAIが自動生成
2. Markdownエディタで編集
3. セクションを追加・削除・並べ替え
4. 完成したらエクスポート

**完了条件**:
- 設計書の内容が記述されている

**エクスポート形式**:
- Markdown (.md)
- PDF（準備中）

## リアルタイム共同編集

### 編集の同期

- 他のメンバーの編集がリアルタイムで反映されます
- 編集中のユーザーがアバターで表示されます
- カーソル位置も共有されます

### 競合の解決

- 同じ箇所を複数人が編集した場合、最後の保存が優先されます
- 競合が発生した場合は通知が表示されます

## コメント・レビュー機能

### コメントの追加

1. テキストを選択
2. 右クリックまたは「コメント」ボタン
3. コメント内容を入力
4. 「投稿」をクリック

### コメントの解決

1. コメントパネルで該当コメントを表示
2. 「解決済みにする」をクリック

### レビュー状態

各フェーズには「レビュー待ち」「承認済み」のステータスを設定できます。

## 変更履歴とロールバック

### 履歴の確認

1. 「履歴」タブを開く
2. 変更内容を時系列で表示
3. 差分を確認

### ロールバック

1. 履歴から戻したいポイントを選択
2. 「この状態に戻す」をクリック
3. 確認ダイアログで「OK」

⚠️ **注意**: ロールバックは慎重に実行してください。ロールバック後の変更も履歴に記録されます。

## AI支援機能の活用

### AI支援の種類

| フェーズ | 機能 | 用途 |
|---------|------|------|
| アイデア | 要約 | アイデアの整理 |
| アイデア | カテゴリ分け | アイデアの分類 |
| 要件定義 | 変換 | アイデアを要件に変換 |
| 要件定義 | 検証 | 曖昧さ・抜け漏れチェック |
| 設計計画 | 整合性チェック | 要件との整合性確認 |
| 設計書 | 生成 | 設計書の自動生成 |

### AI提案の採用・破棄

AIの提案は必ず人が確認して採用・破棄を決定します：

1. AI支援機能を実行
2. 提案内容を確認
3. 「採用」または「破棄」を選択
4. 採用した場合、データに反映されます

### 信頼度スコア

AIの提案には信頼度スコア（0.0〜1.0）が表示されます：
- 0.9以上: 高い信頼性
- 0.7〜0.9: 中程度の信頼性
- 0.7未満: 確認が必要

## エクスポート機能

### 設計書のエクスポート

1. 設計書作成フェーズで「エクスポート」をクリック
2. フォーマットを選択（Markdown / PDF）
3. ダウンロードリンクが生成されます
4. リンクは30日間有効です

### エクスポート履歴

過去のエクスポート履歴を「履歴」タブで確認できます。

## トラブルシューティング

### 接続が切れた場合

- ページをリロードしてください
- WebSocketは自動的に再接続を試みます

### 編集が反映されない

1. インターネット接続を確認
2. ブラウザのキャッシュをクリア
3. ログアウト後、再ログイン

### AIが応答しない

- AI APIのレート制限に達している可能性があります
- しばらく待ってから再試行してください

## ベストプラクティス

### プロジェクト管理

- 定期的にバックアップ（履歴）を確認
- 重要な変更前にはコメントで通知
- フェーズごとにレビューを実施

### 共同編集

- 編集前に他のメンバーの作業を確認
- 大きな変更は事前にコメントで提案
- 定期的に保存（自動保存もありますが）

### AI活用

- AI提案は必ず確認してから採用
- 信頼度スコアが低い場合は特に注意
- AI提案を参考に、人が最終判断
